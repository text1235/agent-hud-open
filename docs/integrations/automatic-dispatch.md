# 项目自动协作与验收

所属项目根目录：{{PROJECT_ROOT}}

## 自动判断

收到任务后，由当前 Codex 聊天判断是否值得派工。简单问答、小改动和协作成本高于收益的任务直接完成；可独立执行、边界清楚且有实际收益的实现、资料整理或复核任务，可交给大肥鱼或 Antigravity。原任务范围内的常规派工已获授权，继续完成派工、交付和独立验收，无需逐步再问用户。

Codex 负责理解需求、选择执行端、限定权限、审查成果和最终交付。按执行端当前能力、可用性和任务特点选择，不要求每次两端都用。工具不可用时先检查与本任务直接相关的原因，能自行完成则继续完成。账号访问、额外权限、不可逆操作和强制结束进程仍按用户及项目原有约定处理。

## 项目与办公区

任务归属上面指定的实际项目根目录。按本次需要创建 `协作办公区/大肥鱼/<任务名-唯一ID>` 或 `协作办公区/Antigravity/<任务名-唯一ID>`；Codex 的核验证据放在 `协作办公区/Codex验收/<任务名-唯一ID>`。记录所属项目根目录和本次办公区绝对路径，明确允许读取的输入、允许修改的文件、目标和可核验标准。原始资料按授权就地读取，避免复制整个项目；两端不同时修改同一正式文件。验收通过后再合入原有正式目录，覆盖时保留可恢复版本。

## 大肥鱼：Hermes Gateway

“大肥鱼”指本机 Hermes 智能体。优先使用现有 `hermes_gateway` MCP，执行前读取 `Z:/Hermes/project-gateway/REVIEW_WORKFLOW.md` 并检查当前服务。按实际项目根目录注册 Gateway，提交明确目标、边界、验收标准和唯一 `request_key`；返工用 `parent_id` 关联原任务。

每个 Codex 聊天使用独立验收队列，记录精确项目 ID、当前聊天 `thread_id`、root/parent 链、任务和验收轮次。当前轮结束前，用 `gateway_bind_delivery` 绑定精确任务、原聊天 `CODEX_THREAD_ID`、独立队列及本机 Codex 可执行路径，并查询确认。终态事件回到原聊天后先 `gateway_delivery_ack`，再独立核验。`queued` 表示事件入队，`consumed` 才表示原聊天确认；无法绑定时如实说明。使用事件投递，保持未变化状态安静，不另建周期轮询。

`completed` 表示执行端交付。Codex 必须检查实际文件、改动和必要验证，保存证据后调用 `gateway_review accepted/rejected`。不合格时先确认无 `queued/running/uncertain` 后代，再关联原任务提交针对性返工，继续完成原验收标准。状态未知时先查清，避免重复派工。

## Antigravity：现有协作工作台

使用现有 `collaboration_workbench` MCP 的 `workbench_status`、`antigravity_submit`、`antigravity_get_task`、`antigravity_review`；可用时通过 `antigravity_models` 查看实时目录和额度。工作台位于 `Z:/Hermes/workbench`。明确实际项目绝对根目录、办公区、具体目标、边界、验收标准和唯一 `request_key`。默认 `model=auto`：派工前实时检查模型可用性和额度；Argon High 余额高于 10% 时优先使用，降到 10% 或以下时优先切到有额度的 3.8 Flash High 等模型。目录缺失、禁用或余额未知不当作可用；没有余额高于 10% 的可用模型就停止发送。记录请求模型、实际模型、额度与切换原因，核对真实桌面会话的项目和执行模型，保留原生审批。返工用 `parent_id` 关联本轮任务；发送状态未知时先查原任务，不能换模型重复发送。

所有执行端都要先检查实际服务和模型是否可用；不能把历史可用当作本次已验证。大肥鱼优先 Mercury 3 私有网关 / high；接口不提供余额时如实记为未知，不能编造额度。有明确额度或模型不可用错误时，在核实原任务已终止后才选择已配置且获授权的可用模型或执行端，保留原项目、权限及验收边界，不新建账号或修改计费设置。

在当前活动轮跟踪至交付和验收。Codex 独立检查实际文件并执行适当验证，记录 `accepted/rejected` 及证据；`SUCCESS/completed` 或执行端自述不能代替验收。接口没有与 Hermes 等同的原聊天终态唤醒绑定，按真实能力报告，不声称已设置自动唤醒。未知状态先读取原任务，避免重复提交。

## 交付与资源

只向执行端提供当前任务必要信息，保留其他项目、聊天队列、用户原有程序和 Hermes 微信连接。执行端不得递归转派 Codex。临时测试程序记录路径、PID、启动时间和所属任务，保存结果后正常退出并检查残留；用户明确要求保留的服务除外。需要强制结束进程时，先核对身份并取得明确同意。

HUD 用真实工作台状态显示派工、执行、交付和已记录的验收结果；最终验收由当前 Codex 聊天完成。
